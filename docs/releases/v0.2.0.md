# v0.2.0 — Real and secure MQTT boundary

## Release purpose

Version 0.2.0 moves the evidence pipeline across a real MQTT transport and adds
an independently reproducible authentication and authorization boundary. It
finalizes milestones M7 and M8 without changing the canonical event, ledger,
projection, quality or bundle contracts delivered in v0.1.0.

## Verified evidence

- A pinned Mosquitto broker delivers retained QoS 1 messages to the Paho
  consumer and durable SQLite ledger.
- The consumer resumes ingestion after a controlled broker stop and restart.
- TLS verifies the broker hostname and requires a trusted client certificate.
- Certificate identities separate publisher and consumer permissions.
- Connections without a client certificate and with an untrusted certificate
  are rejected.
- A trusted read-only identity cannot publish evidence into the ledger.
- Broker health probes use a separate identity and topic and cannot contaminate
  the evidence hierarchy.
- Python 3.11, Python 3.12, real-broker and secure-broker campaigns run in CI.

## Data and credential boundary

All public events, identities, locations and measurements are synthetic. Test
certificates are generated at runtime, are valid for two days and are excluded
from version control. No LandSky identity, deployment configuration, location,
credential or private operational record is included.

## Explicit non-claims

This release is not a production MQTT or PKI certification. It does not prove:

- certificate issuance, rotation or revocation operations;
- hardware-backed or otherwise protected private-key custody;
- enterprise identity-provider integration;
- availability across real networks or long-duration deployments;
- sensor accuracy, domain interpretation or safety-critical suitability;
- authorization for the system to control physical equipment.

## Compatibility

No migration is required from v0.1.0 for the canonical event schema, SQLite
ledger, state projection, quality findings or evidence bundles. TLS is optional
in the concrete Paho consumer so the bounded M7 loopback integration fixture
remains reproducible.

## Reproduction

Follow the real-broker and mutual-TLS commands in the repository README. The
secure campaign requires Docker, Docker Compose and OpenSSL; generated
credentials must not be reused outside the test campaign.
